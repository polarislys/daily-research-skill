# daily-research 写作语言（必读）

落盘前读本文。标杆：[宝玉《Warp 如何让 Agent 自我进化》](https://mp.weixin.qq.com/s/1YaHaOC1veK3dJhlJyvE9Q)。

## 篇幅

- **目标约 2000 汉字**（可 1800～2500），只挖 **1～2 个问题点**，但要写透，不要短讯体。
- 一半篇幅给 **机制**：为什么这样设计、环怎么转、和相邻方案差在哪、边界在哪。

## 你要写的是什么

读完能带走一个判断的技术短文：问题 → 以前为什么不行 → 机制深入 → 对照与边界。  
术语保留（harness、DPO、Skill…），句子顺，像宝玉那样讲，不要 wiki 填表。

## 结构（灵活）

```text
# 判断句标题

开篇：这篇只答什么；为什么值得看。

## 痛点 / 背景
## 机制（深入，可分子节）
## 对照、误区或还没证实的一点
---
**参考** [标题](https://...)
```

禁止：「这是个啥」「一句话」块、代码块里放 URL。

## 落盘

```text
output/<短标题>-<YYYY-MM-DD>.md
```

**不要子文件夹。** 形态、主题写在文首 YAML frontmatter：

```yaml
---
形态: 产品剖析 | 新方法 | 新闻动态
主题: Warp
日期: 2026-09-06
---
```

收件箱：`output/收件箱-<YYYY-MM-DD>.md`（同样不要文件夹）。

## 自检

1. 字数是否接近 2000？机制是否够深？  
2. 删掉模板小标题还能读顺吗？  
3. 像宝玉长文，还是像简报？
