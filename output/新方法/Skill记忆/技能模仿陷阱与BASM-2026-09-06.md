# 只从成功轨迹里抽 Skill，检索越多越敢调错工具

形态：新方法  
大主题：Skill记忆  
日期：2026-09-06（Asia/Shanghai）  
问题点：Skill Imitation Trap 是怎么被测出来的？BASM 往 Skill 上多写了哪几个字段？  
候选：BASM、Skill Imitation Trap 尚未晋升

## 先说清楚

美团与中科院自动化所 2026-08-23 的预印本 [When Not to Imitate](https://arxiv.org/abs/2608.22339) 点名一个流行假设：把成功轨迹蒸馏成 skill memory，检索进来就应该单调变好。探针发现相反的情况——任务和旧成功长得像、该换工具时，**检索到的 procedure skill 越多，模型对错误工具越自信**。相对无记忆基线，错误工具的优势间隔（wrong-tool margin）升高 47%。他们把这个失败叫 **Skill Imitation Trap（技能模仿陷阱）**。

对策是 **BASM（Boundary-Aware Skill Memory，边界感知技能记忆）**：每条 skill 除了目标、步骤、工具，再写适用条件、风险线索、回避规则、恢复笔记。检索到的不再是「无条件模板」，而是「当前状态允不允许套这套步骤」。实验在 AppWorld / BFCL / AgentDojo、四个模型规模上，相对「只蒸馏成功」的记忆基线有增益。这是方法论文，不是产品。

## 问题只圈这些

只讲陷阱怎么被测出来，以及七个字段和在线检查怎么转。不讨论该不该上生产。

## 原理

**skill memory**：从过去轨迹抽出可复用的程序性知识（怎么做、用哪些工具），下次语义相似就检索进来。Voyager、ExpeL 一路都默认：检索命中 ≈ 正迁移。BASM 说漏写的是 **validity boundary（有效边界）**——「长得像」不等于「现在还能这么干」。

**Skill Imitation Trap 的测法**：

1. 构造「表面像旧成功、工具必须换」的探针任务。  
2. 加大检索条数，看模型对错误工具的置信差。procedure skill 让 wrong-tool margin 相对无记忆升高 47%。  
3. 注意力分析：检索内容一匹配当前问句，模型把注意挪到步骤正文，而不是「现在能不能用」。  
4. 同提示敲除（knockout）边界字段对应的注意跨度，能收回 69.4% 的模仿效应——说明边界字段是一条因果通道，不是装饰。

**BASM 的七槽**：

| 槽 | 管什么 |
|---|---|
| goal / procedure / tools | 程序性核心：做什么、怎么做、调谁 |
| applicability | 适用条件：什么状态才能套 |
| risk cues | 风险线索：什么时候像但不该套 |
| avoidance | 回避规则：明确禁止的工具或步骤 |
| recovery | 恢复笔记：执行偏了怎么局部修 |

在线三步：按 token 预算检索并**选择性地露出边界证据**；prompt 侧 boundary checker 决定 apply / suppress / repair；有状态环境里再用 runtime repair 做局部修补。探针还显示：风险态和修复态比安全态更常去看边界字段。

和相邻方法两句差：普通 success-distilled skill memory 假设「相关即有用」；BASM 把相关拆成「语义相关」和「决策仍有效」。和 skill-rag 的差：rag 解决的是「选哪一条」，BASM 解决的是「选中了也不许当无条件模板」。和 Warp 那种「人评论改 SKILL.md」也不是同一层：BASM 改的是记忆记录的图式，不一定经过人审 PR。

数字（论文摘要，相对成功蒸馏基线或无记忆基线，以原文表格为准）：AppWorld 任务成功率最高 +23.8%；BFCL 准确率最高 +5.0%；AgentDojo 攻击成功率 −4.6%；AppWorld 平均步数相对无记忆最多 −6.6%。模型从约 8B 到 397B。
