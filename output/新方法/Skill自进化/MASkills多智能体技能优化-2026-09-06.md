# MASkills 不改权重，改的是一队 agent 各自的 SKILL.md

形态：新方法  
大主题：Skill自进化  
日期：2026-09-06（Asia/Shanghai）  
问题点：多 agent 时，团队成败怎么记到某一条 Skill 头上？语言空间里的「梯度」实际是哪四个编辑动作？  
候选：MASkills 尚未晋升

## 先说清楚

[MASkills](https://arxiv.org/abs/2609.02094)（2026-09-02，EMNLP 2026 Findings）把持续学习的对象从参数挪到 **skill 空间**：每个 agent 带着自己的技能库 `{SKILL.md, skill.yaml, 脚本/资料}`，优化目标是这些文件，不是 θ。它针对的失败是：Reflexion 一类经验记忆能记下「发生过什么」，但不好调用、不好改、一长大就和噪声搅在一起；现有 skill 进化方法又多半是单 agent，吃不到「队友的技能把团队分摊走了」这种归责。

流水线按语言空间里的策略梯度类比来装：技能条件信用分配、分层汇总、动量平滑，再驱动 refinement / induction / consolidation / pruning，并带持有验证和回滚。实验在 HotpotQA、LoCoMo、GAIA。代码声称在 [DaRL-GenAI/MASkills](https://github.com/DaRL-GenAI/MASkills)。

## 问题只圈这些

只讲「信用怎么落到 skill」和「四个编辑算子」。不把 TextGrad 重讲一遍。

## 原理

**记忆 vs skill**：记忆是轨迹摘要，调用条件含糊，越积越脏。Skill（按 Anthropic / agentskills 的用法）是程序性包装：何时调用、怎么做、用哪些资源。元数据短、正文按需加载，这就是渐进式披露。MASkills 认 skill 是比记忆更可优化的单元。

**多 agent 多出来的三难**：

1. 团队奖励要记到**某次技能调用**，不是只记到某个 agent。一条 skill 可能只在少数时间步出现，又和别人的行为缠在一起。  
2. 从轨迹抽出的语言反馈又吵又不稳定；中心规划和点对点通信的归责路径还不一样。  
3. Skill 是离散文件。改错一步等于改了动作空间，不能当连续参数那样小步滑。

**技能条件信用**：语言 critic 做反事实比较——「当时若没调用这条 skill，轨迹反馈会怎样」——把优势记到 (agent, skill) 。这是 credit assignment 在 skill 层的版本，和 TIGPO 给环境动作打步级分不是同一张图，对象变成了文件化规程。

**分层汇总 + 动量**：先在一批轨迹里按时间 / agent / skill / 交互拓扑汇总，再跨学习周期做动量平滑，减轻单次嘈杂评论把库带飞。

**四个算子**（信用稳定之后才动文件）：

- refinement：改已有 SKILL.md 的步骤或条件  
- induction：从轨迹归纳出新 skill  
- consolidation：合并重复  
- pruning：剪掉低信用或有害条目  

更新后走持有验证，不好就回滚。论文把这些叫语言空间里的伪梯度：采样是 rollout，优势是 critic 的话，更新是文件编辑。

和 BASM 两句差：BASM 改的是单条记忆的**边界字段**，防止成功模板被乱套；MASkills 改的是**一队人的技能库怎么随着团队奖励长**，并显式做归责和回滚。和 Warp 两句差：Warp 的监督是人在 PR 上的评论；MASkills 的监督是轨迹上的语言 critic，人可以不在环内——这也是高风险处，所以他们加了验证和回滚。

## 它还证明不了什么

- 环境是问答和 GAIA，不是生产多 agent 退款系统。  
- 「语言梯度」是类比，没有可反传的导数。  
- GitHub 仓库本日只按论文自报收录，未在本文逐文件核过实验脚本。  
- 投稿 2026-09-02，落在约 24～96 小时的论文窗，不是 9 月 6 日当天新文。
