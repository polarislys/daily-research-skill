# HarnessEvolve 用参考轨迹对准失败第一步，再用两道门挡住捷径

这篇只答一个问题：让 Agent 自己改 harness——prompt、Skill、工具、执行逻辑——为什么会在稀疏终局信号下改错、抄答案、把旧能力改没？华为 ICT 的 [HarnessEvolve](https://arxiv.org/abs/2609.00829)（2026-09-01 投稿）不训练权重，把执行和进化拆成四个模块，用「带着标准答案再跑一遍」的参考轨迹给中间步骤打功过。

## 旧的自进化为什么站不住

harness 是包在模型外面的那一层循环、工具、权限和文件化程序。权重冻结时，改这段外部基础设施就能改任务表现。早期工作流写死在图里，偏一点整条管道断。[Claude Code](https://www.anthropic.com/news) 一类 Skill 增强 Agent 放开了试错，但能力仍被人手写的 Skill 卡住，规划错了就在重试里打转。于是出现「根据环境反馈自己改 harness」这条线。

现有框架多半只拿到终局对错。长程任务里，后面的错常常是前面走偏的下游后果，整段反思会对错位置。[HarnessEvolve 论文](https://arxiv.org/abs/2609.00829) 把 GEPA、ACE、SkillOpt 写成各自动一层：prompt、上下文、或单份 skill.md，其余不动。文中点名的 Self-Harness 与 Agentic Harness Engineering 已经开始改整份 harness，但仍缺参考轨迹定位根因、缺泄漏检查、缺快照池——本文把自己放在这三道缺口上。没有对照的成功路径时，优化器容易走两条捷径：把失败题的问与答写进 harness（数据泄漏），或堆一堆题面示例把上下文撑满（prompt bloat）。每次更新又只看见当前这一批轨迹，和上一批学到的程序打架，旧能力被覆盖。论文把这三件事叫 credit assignment failure、shortcut learning、catastrophic forgetting。

credit assignment 是稀疏终局奖励下给中间每一步打功过。这里的「步」不是 token，是一次工具调用或一次规划决策。没有对照轨迹，优化器只能猜。

## 参考轨迹怎么把功过钉到第一步

HarnessEvolve 把执行 Agent 从进化管道里拆出去，四个模块各干一件事，执行方不能给自己打分。

**执行。** 当前 harness 跑训练集。优化开始前，同一套执行 Agent 再带上标准答案跑，最多试若干次。评测模块要确认这条轨迹是真跑出来的：该调的工具调了，中间观察被消化了，答案不是把给定标签抄回去。通过的才进全局缓存，叫参考轨迹。全部尝试都假或都错，这道题就没有参考，优化时退回单轨迹分析。

**评测。** 一批里对照最终输出和标准答案，失败轨迹交给优化。参考轨迹的「像不像真做题」也由评测模块单独判，执行模块不能自证清白。

**优化。** 失败轨迹和参考轨迹对齐，找**第一次动作分叉**。分叉之后的偏离多半是连锁反应，不当独立根因。每条失败产出结构化错误信号：严重度、原因（工具幻觉、漏参数、过早结束等）、自然语言修复提示。再按原因聚类，而不是按严重度糊成一堆；单成员簇保留，避免稀有但致命的失败被大簇吃掉。优化器按簇的规模和严重度改 harness，输出一组候选补丁。它改的是整份 harness——Skill 目录、参考文件、脚本、prompt、工具——不是单份 skill.md。

**两道门。** 质量门检查候选有没有把失败题的问答嵌进文件、新注入的 in-context 例子有没有超上限；超了退回重写，次数用尽就丢弃。论文里泄漏分用 LLM-as-judge，超过 η_leak=0.8 拒，新例子超过 η_blo=5 拒，最多改三轮。性能门更狠：当前这一批准确率至少不降（δ=0.0），对最近 R=2 批的回退不能超过 ε=0.025。过门的快照进池子，立刻变成后续批次的当前 Agent。一批连续拒满 10 次，本 epoch 提前结束，避免收敛后空转。一轮结束，用验证集从池子里挑最好的那张快照，而不是「最后一次改过的那版」。验证集连续 5 个 epoch 不涨，或跑满 20 轮，就停。

参考轨迹不是「把答案贴进 prompt」。生成时执行 Agent 仍走工具环，评测要看见合法推理链；直接复述标签的轨迹进不了缓存。没有参考的题不是扔掉，而是退回单轨迹分析——消融证明这条退路很弱，所以缓存覆盖率几乎决定进化上限。聚类按原因不按严重度，并保留单成员簇：漏参数和过早结束不能合成一条「再仔细一点」的补丁。

消融把主因钉死。CloudCoreNetwork-QA、Qwen3.6-27B 上，完整系统 86.9%；拿掉参考轨迹掉到 57.8%，拿掉错误聚类到 68.6%，拿掉质量门到 80.1%。参考对照是最贵的那一刀：没有「成功时第一步该干什么」，后面的门再严也在修症状。质量门不是装饰，去掉会掉 6.8 点，说明优化器在有标准答案的设定里确实会抄。

数字按论文表走。企业内部两套题：CloudCoreNetwork-QA 上 Qwen 从 Base 43.4% 到 86.9%，比最强基线 GEPA 的 65.3% 高 21.6 点；Wireless-QA 上 DeepSeek-V4-Flash 到 92.8%。开源三套 SearchQA / OfficeQA / SpreadsheetBench 分别到 92.9 / 70.9 / 76.4，全部最高。把在 OpenClaw 上优化过的 Skill 原样挂到 Hermes、OpenCode、LAMAgent、DeepSeek Harness，四套都维持或上升；SpreadsheetBench 上 OpenCode 从 57.5% 到 87.9%，DeepSeek Harness 从 56.4% 到 86.8%——论文据此说改到的是一般错误模式，不是某一框架的口头禅。企业题在自研 LAMAgent 上优化整份项目代码；开源题在 OpenClaw 上优化 skills、AGENTS.md、SOUL.md 和工具。两种宿主都能涨，说明方法不绑死一种文件布局。

## 还依赖什么、不能当成已上线产品

参考轨迹需要标准答案。开放网上没有标签的长程任务，这套诊断退回单轨迹反思，也就是消融里最差的那一档。评测模块用模型判断「像不像真做题」，本身会漏过更隐蔽的抄答案。质量门的泄漏阈值和例子上限是超参，设松了捷径会溜进去。企业两套题是华为内部数据，外部只能核对开源三套和跨框架迁移表。论文没有发布可复现的训练代码仓库链接。

它和昨日 [TIGPO / PGPO](TIGPO与PGPO-credit-assignment-2026-09-06.md) 的差在优化对象：那两篇改策略梯度里的优势估计，这篇改可 diff 的 harness 文件。和 [SkillGLoW](https://arxiv.org/abs/2609.02217) 的差在门禁语义：GLoW 用下游执行分数决定一条 prior 能不能进库，HarnessEvolve 用参考轨迹决定**该改 harness 的哪一步**，再用泄漏检查和跨批次回归决定改完能不能留下。工程上可复查的一点：若你已经让 Agent 改 SKILL.md，先问三件事——失败轨迹有没有一条「带着答案再跑」的对照、候选补丁有没有被查过是否抄题、提交前有没有在最近几批上回归。三问缺一，自进化就还是终局对错加一篇反思。
