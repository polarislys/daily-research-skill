# Skill 不该是一篇大文档，也不该一人一条——SkillGLoW 按程序族压缩

这篇只答一个问题：Agent 自己写出来的 Skill，该按什么粒度存？新加坡国立大学与 IAIC 的 [SkillGLoW](https://arxiv.org/abs/2609.02217)（2026-09-02 投稿）说，长程、解法彼此不同的任务流上，现有两种存法会朝相反方向坏：一篇全局文档塌成空话，扁平的一人一条库则膨胀且绑死实例。中间缺的那一层，是一簇相关任务共享的解题程序。

## 两种存法为什么会同时失败

Skill 在这里就是一段自然语言程序，塞进冻结 Agent 的上下文里；改这段文字是论文唯一能动的旋钮，环境给的 verifier 分数是唯一可信的效果。harness 负责跑、打分，模型权重不动。[SkillsBench](https://arxiv.org/abs/2609.02217) 已经给过对照：人写的 Skill 能把通过率抬 16.2 点，模型只看题面自己写的，反而比无 Skill 基线低 1.3 点。所以新方法都改从真实轨迹里蒸馏。可蒸馏完往哪放？

一篇全局文档默认「大多数任务共用一套程序」。任务长、解法散的时候，文档只能留下「先规划、再验证」这类纪律，对下一道具体题没有抓手。[SkillOpt](https://arxiv.org/abs/2609.02217) 把这一篇文档当冻结 Agent 的外部状态来优化，在 ALFWorld 这种动作空间高度共享的环境里仍然好用；换到 Terminal-Bench-Pro 或 SWE-bench Verified——每道题一个仓库、一套解法——它就没有主导程序可总结。

扁平库默认「旧条目可以整段复用」。条目跟着写出它的那次成功走，检索再准也只是把「某次修某个仓库的步骤」塞给下一次。论文在同一任务流上测了单文档、扁平库、再加检索三种组织，家族压缩都赢：差不在 embedding，在**存的单元选错了**。相似任务会成族，族内共享解题骨架；实例约束只在当场执行时出现。该跨任务带走的是程序，不该带走的是那一次的路径、文件名、报错原文。

## 程序族怎么织进两条层

GLoW 把 Skill 拆成两层，解题时织在一起，巩固时再拆开。

**当场只写本地。** 对当前任务先召回已提交的全局 prior（一个永远注入的 base，加上相似度过门槛才注入的族 prior），跑一遍。然后 Localize 只看这次任务相邻几次轨迹的差，加上 verifier 分数，判断哪些改动真推进了任务，写成一份本地 Skill。这份东西**不查历史库、不写回长期库**。封装成 skill card：题面、抽象签名（这次解法做了什么）、轨迹、分数、本地 Skill。签名权重最高、Skill 正文权重最低，后面聚类跟的是「怎么解」而不是「题面怎么写」。

**线下按族压缩。** 一轮任务流跑完，对 card 做多次层次聚类、记成对共现，再在共识相似度上切族，族数由 silhouette 曲线的膝点自动定。每个族压成一条候选 prior：只留适用条件、核心解题程序、常见失败模式。实例细节故意丢掉，下次执行时由新的本地 Skill 现写。库的大小跟发现了多少种程序走，不跟见过多少道题走。十二次持续改进里，已提交库比一人一条池平均小 3.6 倍。

**提交看执行，不看文本漂不漂亮。** 压缩会放宽规则、丢掉约束，字面上看不出来。门禁只拿「纯全局 prior、不附加本地 Skill」在任务集上的 verifier 均值。一轮里有三条路出候选：本轮新压缩、在退化任务上追加范围受限的守卫、以及各族历史最高分版本。整库一起比，只有不低于当前库与无 Skill 基线（再加 0.02 的波动容差）才提交；通不过就原库不动。这和「改了 Skill 文件就直接上线」相反：文本再顺，也要被真实执行否决。十二次运行里门禁做了 26 次决定，收 19 拒 7；软件修复三次都是第一轮收、第二轮拒。4 次拒绝若只看巩固时的软分数会放行——MiniMax-M3 在数学上有一条候选软分 0.283 过锚，部署 hard 只有 0.151，掉 13.2 点。门禁留下的库最后一轮平均 +14.7，无条件收下当轮候选只有 +9.6。

同一套十二次运行上，三种替代组织都弱一截。把全库压成一篇（Base-only）平均只 +2.0，12 格里 4 格还是负的；只用当场重生的本地 Skill（Local-only）+10.9，但仍低于纯全局 prior，而且条目跟实例走、库随题数线性涨。给扁平池加上检索（AWM 风格）平均 +5.0，8 升 3 降 1 平。家族巩固一轮就是 +11.2。差再次落在单元，不在检索器。

**解题时全局冻结。** 召回在任务开始前完成，整段执行期间 prior 不改。查询是题面 embedding，对象是每条已提交 prior 的全文，阈值 0.45 跨 benchmark 共用，低于就只留 base，fail-closed。Agent 先在 prior 下跑，再根据当场反馈重生本地 Skill，上下文变成 prior ⊕ 本地。本地只当本轮证据，下线再进巩固。未改过的库把未见过的 ALFWorld 任务成功率从 73.9% 抬到 83.9%；MiniMax-M3 在 30 个未见软件修复实例上 resolve 从 40.0% 到 45.6%——搬走的是程序，不是那几道题的记忆。

压缩丢什么、留什么，可以对照原文。ALFWorld 的 examine-in-light 本地 Skill 用 989 词记一张家具位置表；压成的族 prior 剩 440 词、四步，表没了，第一步改成「扫初始观察里的照明类物体，对照可见列表再 go to」。七道题共享的是「别把步数花在不增加信息的探查」，哪件家具里有灯由本地现写。42 道题压出 15 条 prior，13 条落在数据集自己的类别标签里，没有发明新类，也没有空着一类。反例也写在纸上：Terminal-Bench-Pro 里一个八题大族把调试、WAL 恢复、逻辑门 CRC32 揉在一起，净收益为零；换一个模型在同一 32 题上切出十个族、每族不超过五题，才有净修复。族是每一轮从当场证据重切的，坏切不会被写死。

实验用 DeepSeek-V4-Pro、MiniMax-M3、GPT-5.4-mini 三个冻结模型，扫 Terminal-Bench-Pro、SWE-bench Verified、ALFWorld、LiveMathematicianBench，十二次全正增益。冻结 prior 相对无 Skill 基线平均 +17.2 个 hard 点，加上本地重生到 +18.0。最大增益落在软件修复那一端（MiniMax-M3 +30.0），数学那一端反而最小——正是框架预测的顺序：一族一种程序，在「没有主导程序可写进一篇文档」的地方才值钱。同一协议下 GLoW 在 21 个格子里赢 SkillOpt 15 个；SkillOpt 赢的 4 个全在 ALFWorld。

## 还不能外推的一点

库要靠 verifier。没有可执行检查器的开放域，门禁会退化成模型自评，论文没证这一步还稳。聚类和压缩本身也是 LLM 调用，族切错会把不该在一起的程序揉成一条 prior。四个 benchmark 的题量是 32 / 20 / 42 / 53，SWE 数字还是三次试验平均，不是大规模生产库。Localize 依赖同一任务多跑几次，预算紧的线上环未必给得起。

跟昨日写的 [BASM](https://arxiv.org/abs/2608.22339) 不打架：BASM 管检索到了该不该用，GLoW 管长期该存哪一层。可以叠：入库的 prior 带上 boundary 字段，进化才不会把错模板压进族里。跟 [MASkills](https://arxiv.org/abs/2609.02094) 的差是优化对象——MASkills 改各 Agent 的 SKILL.md 文本，GLoW 改的是**库的粒度**。工程上可复查的一点：你的 Skill 库若只有「全局 AGENTS.md」或「每任务一份笔记」，先数一数实际有几类解题程序；类数远小于题数，就该按族压，而不是再往文档里追加纪律，也不是再往池子里追加实例。
