# DeepSeek Harness 把循环本身也做成可替换插件

形态：产品剖析  
大主题：DeepSeek-Harness  
日期：2026-09-06（Asia/Shanghai）  
问题点：dsh 的「一切皆插件」具体拆成哪些缝？它和 Unix 老命令、汽车座舱 OpenDSH 是不是同一个东西？

## 先说清楚

DeepSeek Harness 的 CLI 名是 **dsh**，仓库在 [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)，2026-08-13 以开发者预览开源，MIT。一句话：独立进程，自带配置、会话、权限；核心只留循环和抽象缝，能力全部用 **Cordis** 插件拼出来。它不是聊天框，也不是 IDE 补全插件。

核心理念写在项目标语里：Everything is a Plugin。模型适配、工具、skill、会话、沙盒、存储、循环、调度、UI，都可以在不改核心源码的前提下替换。这和 Codex「开一条官方环，用 exec/SDK/app-server 接进去」是反方向：Codex 把环做成稳定协议；dsh 把环做成可拆插件树。

## 问题只圈这些

只拆插件缝和运行形态。不评 DeepSeek 模型版本，不把 Hermes、Codex 写成一家。

## 它由什么构成

**Cordis**：组合框架，插件往共享 `ctx` 上挂服务、带类型的事件、可逆效果。社区文档把关键缝写成 `ctx.llm`、`ctx.tools`、`ctx.sandbox`、`ctx.sessions`、`ctx.agentLoop` 这类键。换模型 = 换 llm 插件，不是改 agent 主循环里的 if-else。

**Profile**：一次启动时插件的叠层配置。官方应用以 profile 区分：`dsh web`（本地工作台，文档写默认 `http://127.0.0.1:3080`）、`headless`、`sdk`、`sdk-minimal`、`acp`。同一套启动器，不同的插件包。

**会话**：独立进程，配置和会话落在 `~/.dsh/`（社区文档）。会话日志被写成 append-only 的 `SessionEvent`，这是观测面，不是事后从聊天记录反推。

**权限与沙盒**：也是插件，不是外挂防火墙。预览期接口会破，官方自己把 v0.1 标成 developer preview。

**和两个同名物的差**：Unix 老命令 `dsh` 是 distributed shell；[OpenDSH](https://opendsh.com/) 是汽车数字座舱。检索「dsh harness」时不要把这两条收进 Agent 产品。

## 理念怎么落进机制

主线：**可替换的是缝，不是皮肤。**

若循环硬编码在一个大文件里，换工具协议等于分叉仓库。dsh 把「循环也可替换」写进架构：`core/agent-loop` 只是默认驱动，挂在 `ctx.agentLoop` 上。这对实验友好——可以留一条最小 loop 做对照——对要冻结行为的产品不友好：预览期任何插件接口都可能改名。

社区站扫过 npm 上带 `cordis.patch` 的第三方包数量，那是二手扫描，不是 DeepSeek 公告，本文不当作官方生态规模。要核对，只打开官方仓库的 `packages/` 和文档里的 profile 列表。

和 Codex 对照（只为说清缝，不比较胜负）：Codex 的稳定面是 JSON-RPC 事件；dsh 的稳定面（目标）是 Cordis 的 ctx 键。接 dsh 等于接受「组合根在配置文件」；接 Codex 等于接受「组合根在客户端协议」。

预览期读仓库时，先看 `apps/`（cli、web）和 `packages/`（core、llm、mcp、sandbox、context…）的边界，不要从二手「四套 run mode」文章倒推。profile 才是官方启动面：同一条 CLI，换一叠插件。`sdk-minimal` 被写成刻意的例外——单独捆一份，不走默认补丁层——说明他们知道「最小可复现环」和「全家桶 web」必须能拆开，否则评测和演示会搅在一起。

会话 append-only 的实际用处：回放时不应改历史事件，只追加。这让「模型当时见过什么」可核对。若实现里允许改写旧事件，观测面就废了。社区文档提到这一点，仍以仓库里 session 包的实现为准。
