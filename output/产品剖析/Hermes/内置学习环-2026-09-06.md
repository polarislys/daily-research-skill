# Hermes 把「会自己写 Skill」做成产品默认行为

形态：产品剖析  
大主题：Hermes  
日期：2026-09-06（Asia/Shanghai）  
问题点：hermes-agent 的学习环由哪些模块构成？它和文件化 Skill、记忆分别管什么？

## 先说清楚

[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent) 自称「和你一起长的 agent」：任务之后能从经验创建 Skill，使用中改 Skill，用 FTS5 搜旧会话，跨会话建用户模型。仓库 2025-07 已建立；2026-09-05 前后中文资讯再次按「开源发布」传播。更准确的说法是：**产品形态早已在，本周热度又起来。**

核心理念：它不是绑在 IDE 里的编码助手，也不是单 API 的聊天封装。进程可以住在 5 美元 VPS、GPU 集群或 Daytona / Modal 这类可休眠后端；人从 Telegram 说话，活在云端 VM 上跑。模型可切 OpenRouter / 自建端点，不锁一家。

## 问题只圈这些

只拆学习环和运行后端。不评 Nous 的 Hermes 基座模型，不把「唯一内置学习闭环」当成可证伪评测。

## 它由什么构成

**Skill 与 Skill Hub**：兼容 [agentskills.io](https://agentskills.io) 的文件化 Skill；复杂任务后可自动创建，使用中可改。这是程序性知识（怎么做），应当可 diff。若没有人审，自动写入等于往仓库堆不可复现的 markdown。

**记忆与跨会话**：FTS5 搜旧对话，再加 LLM 摘要；Honcho 做「辩证式」用户建模。这是记忆层，和 Skill 分开——和 Warp 官方强调的「Skill ≠ memory」是同一条缝，只是 Hermes 把两边都做成默认功能。

**消息网关**：一个进程接 Telegram、Discord、Slack、WhatsApp、Signal 和 CLI。学习环若只活在单次 TUI 会话里，跨设备就会断。

**定时**：内置 cron，用自然语言订日报、备份、审计。这是调度，不是模型自己「想起来」。

**终端后端**：README 列举本地、Docker、SSH、Singularity、Modal、Daytona、Vercel Sandbox。local 等于本机壳；Daytona / Modal 强调空闲休眠。评测场景下，「可休眠」会让时钟和外部状态漂移，不应当默认。

**研究面**：批量轨迹、轨迹压缩，接到他们自己的强化学习栈（文案提 Atropos）。说明这个产品同时想当日常 agent 和数据收集器。

**LLM Wiki skill**：捆绑 Karpathy 的「由模型维护的交叉引用笔记库」：原始素材 / 编译后的 wiki / schema 三层。人负责供料和提问，模型负责交叉引用。这是上下文管理的一种落法，不是向量库换皮。

## 理念怎么落进机制

主线：**默认会写文件，所以必须能审文件。**

Hermes 把 Warp 里「要专门做一条 improver」的事，做成产品开关：用完就写 Skill、写记忆。好处是个人用户摩擦力低；风险是写作类、无标准任务上会负优化——宝玉对写作自进化 Skill 的批评在这里同样适用。没有 PR、没有「谁的反馈算数」，自进化就是无限 append。

和 dsh、Codex 的差：dsh 卖组合根（插件树）；Codex 卖接入协议；Hermes 卖**活得够久的进程 + 会改自己的文件**。中文 9 月 6 日稿把它写成「新发布」，阅读时以仓库创建时间和 README 为准。

LLM Wiki 那一层值得单独记，但不该和「自动写 Skill」混成一件事。Wiki 的编译页是*关于世界的笔记*（概念、来源、交叉引用）；Skill 是*怎么做事*。Karpathy 的 gist 把 schema 文件（`AGENTS.md` / `CLAUDE.md` 一类）写成「让模型成为守纪律的维护者」的关键配置，人和模型一起改这份规范。Hermes 把它收成 bundled skill，默认路径靠 `WIKI_PATH`。若把会话里的临时偏好写进 Skill，下次任务会被过期口味绑架；若把程序性步骤写进 wiki 概念页，检索会找到解释、找不到可执行步骤。

网关 + cron 说明学习环的时间尺度不是「这一次聊天」。没有跨会话检索，Skill 写了也等于没写——下一端（Telegram）看不见。这是产品组成，不是附加彩蛋。
