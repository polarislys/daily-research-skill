# OpenSandbox 卖的是生命周期 API，不是「我们有容器」

形态：产品剖析  
大主题：OpenSandbox  
日期：2026-09-06（Asia/Shanghai）  
问题点：这个沙盒平台由哪些控制面 / 数据面构成？隔离级别和 MCP 是什么关系？

## 先说清楚

[alibaba/OpenSandbox](https://github.com/alibaba/OpenSandbox)（亦见 opensandbox-group）是 Apache-2.0 的通用沙盒平台：多语言 SDK、统一生命周期 API、Docker 与 Kubernetes。README 直接写给 Coding Agents、GUI Agents、评测、代码执行、RL 训练。server v0.2.0 在 2026-06-15，v0.2.3 在 2026-08-26——不是「本周刚发 0.2.0」。

核心理念：把「不信任代码跑在哪」收成一条 API，而不是每个 agent 自己 `docker run`。运行时（会话、工具总线）和沙盒（隔离）是两层货；OpenSandbox 站在后一层。

## 问题只圈这些

只拆平台组成和隔离级别。不写 E2B / Daytona / Runloop 采购对比。

## 它由什么构成

**控制面**：生命周期服务 +（K8s 上）Operator。管创建、查询、销毁、TTL、池化。业务走 SDK / `osb` CLI / 可选 MCP，不直接对每个 Pod 手写 YAML。

**数据面**：带 `execd` 的沙盒镜像。真正的命令、文件、解释器在这里跑。

**K8s 原语**：`Sandbox`、`BatchSandbox`（一批 N 个，给评测和 RL）、`Pool`（预热）、`SandboxSnapshot`（暂停根文件系统，空闲还资源、稍后续跑）。交互式单租户和批量短命沙盒，用的不是同一种交付。

**网络**：egress sidecar 按 `networkPolicy` 限制出网；ingress 可把流量直接打到沙盒 Pod。OSEP-0002 要把后端接到 [kubernetes-sigs/agent-sandbox](https://github.com/alibaba/OpenSandbox/blob/main/oseps/0002-kubernetes-sigs-agent-sandbox-support.md)，让集群认 SIG 的 CRD，而不是每家自己发明注解。

**隔离级别**（文档写明 K8s 侧可选）：

- 容器，共享宿主机内核（快，逃逸面在内核 CVE）  
- gVisor / Kata（系统调用进用户态或轻虚机）  
- 再往上是 Firecracker 一类微虚机，OpenSandbox 文案未把它写成默认

**和 MCP 的关系**：MCP 只描述工具怎么被发现和调用，**不**保证工具跑在隔离里。`npx` 拉一个 server，默认是你的用户权限。[mcp-auditor](https://github.com/mkrtchian/mcp-auditor) 做的是动态对抗评测，不是隔离本身。NSA/CISA 2026-06 的 MCP 安全指引把「约束并沙盒化工具执行」写成部署方责任。

## 理念怎么落进机制

主线：**先问失败时状态还在不在、出网默认允不允许，再问用哪家 SDK。**

评测要每次干净重建，镜像哈希和网络策略必须冻结；人工排障要留盘。把 snapshot / 可休眠后端用在回归集上，时钟和外部工单会漂。出网若默认允许，模型会「为了装依赖而 curl」，供应链从这条缝进来。egress 只拦 80/443 以外的端口不够，要先写允许域名。

两条到 Pod 的路观测点不同：SDK → API server → CRD，日志在控制面；SDK → ingress → Pod，流量可能绕过现有 trace。选后者就要把 trace id 打到 Pod 标签上。

Pool 和 BatchSandbox 不要当成同义词。Pool 是预热好的空沙盒，换来的是冷启动短、闲时占额度；BatchSandbox 是一次要 N 个、往往短命，换来的是评测 / RL 的吞吐。Snapshot 则是第三种时间：人走开了，根文件系统先冻住，集群资源先还回去。三个原语对应三种失败——等得太久、要不起一批、挂着一堆空 Pod 烧钱——不要用「我们上了 K8s」一句话代替。

GUI agent 和编码 agent 可以走同一套生命周期 API，但镜像不同：前者带显示和输入设备，爆破半径是「能看到的屏幕和剪贴板」，不是一段 Python。本机弹真实 Chrome 让模型点，等于隔离级别掉到本机壳再加一套外设。平台把 GUI 写进 README，是在说镜像目录要分开，不是说隔离可以更松。
