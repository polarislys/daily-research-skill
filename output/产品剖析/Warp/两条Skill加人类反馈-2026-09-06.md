# Warp 的 skill 自进化，靠的是两条 Skill 文件，不是模型权重偷偷更新

**一句话**：人照常写 PR 评论 → base Skill 执行 → improver Skill 读评论改 Skill 文件 → 走 PR、人审通过才生效。

日期：2026-09-06

---

## 这是个啥

Warp 是带 AI 的终端/开发环境。Anthropic 官方案例里，它用 **Claude + 仓库里的 Skill 文件** 做 **skill 自进化**（根据反馈改 Skill，且要人审）。

**Skill**：文件化的程序性知识（怎么做 code review、怎么分诊 issue），可 diff、可 PR，不是每次塞进 prompt 的长指令。

**memory（记忆）**：推理时自动写入、一直在变的上下文；和 Skill 不是一回事。Skill 是稳定规程，改动是故意的。

## harness 在这套里干什么

Warp 依赖外层 **harness**（编排、触发、定时跑 improver）：例如 GitHub Actions、内部 Oz。harness 负责「什么时候读哪份 Skill、怎么开 PR」；**改的对象始终是 Skill 文件**，不是权重。

## 环怎么转

1. **base Skill**：有 PR/issue 时，Agent 读文件按规程干活。  
2. **人**：在 PR/issue 下正常评论，不另填表。  
3. **improver Skill**：定时跑，对照「Agent 说了啥 / 人怎么回」，给 base Skill 提小补丁。  
4. **PR + 人审**：合并才生效，可回滚。

宝玉中文解读把问题收成一句：**Skill 怎么进化？** 有标准、能 PR 的会越改越好；没标准的可能越改越乱。

## 反馈错了怎么办

- 限制谁能改 Skill  
- 至少一处人审  
- 有客观标准（测试过不过）的先建小 benchmark
