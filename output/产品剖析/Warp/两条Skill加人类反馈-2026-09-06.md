# Warp 的自我进化，靠的是两条 Skill 文件，不是模型偷偷变聪明

**一句话**：人照常写 PR 评论 → 一条 Skill 干活 → 另一条 Skill 读评论改 Skill 文件 → 走 PR 人审通过才生效。

日期：2026-09-06

---

## 这是个啥

Warp 是带 AI 的终端/开发环境。Anthropic 官方案例里，它用 **Claude + 写在仓库里的 Skill 文件** 做「自我进化」。

所谓 **Skill**，就是一份写清楚的「办事说明书」（比如怎么 review 代码、怎么给 issue 打标签），放在文件里，可以 diff、可以 PR，不是塞进聊天里的长提示词。

所谓 **记忆**，是运行时自动记下来的零碎偏好，会一直变；Skill 是故意改、改完要人看的规程。别混。

## 环怎么转（只讲这一条）

1. **干活 Skill（base）**：有新 PR/issue 时，Agent 读这份文件，按规矩办事。
2. **人**：不填表，就在 PR/issue 下正常评论——「这条有用」「别建议改这个变量名」。
3. **改进 Skill（improver）**：定时跑，把攒下的评论和 Agent 当时说了啥对照，给干活 Skill **提一个小补丁**。
4. **PR + 人审**：补丁必须合并才生效；改错了可以回滚。

宝玉那篇中文解读把问题收成一句：**Skill 怎么进化？** 有标准、能 PR 的会越改越好；没标准的可能越改越乱。Warp 用「人审 + 只改文件」压住后者。

## 反馈错了怎么办

官方默认会错，所以：

- 限制谁能改 Skill（不是全员投票）
- 至少一处要人点头
- 有客观标准的（测试过不过）先建小基准再收反馈
