# Codex 开源的不是模型，是一条可嵌进别人软件的执行环

形态：产品剖析  
大主题：Codex  
日期：2026-09-06（Asia/Shanghai）  
问题点：Codex harness 由哪几层构成？应用该接 exec、SDK 还是 app-server？

## 先说清楚

大多数人认识的 Codex 是 App、CLI、IDE 插件。OpenAI 在开发者博文里把底下那一层单独命名为 **harness**：帮模型收集上下文、推理、用工具、守住边界、请求批准、把工作带到下一轮。开源的是这层夹具和接入面，不是权重。模型调用和托管服务仍单独计费。

核心理念：不要逼每个团队把工作搬进通用编程助手；把这条环嵌进他们已经在用的界面——工单、看板、调查台。Relay 示例把货运看板、业务 MCP、写操作审批留在应用里，环只负责转和跑。

## 问题只圈这些

只拆「环暴露成哪三层接入」以及「应用和 harness 各该拥有什么」。不评 GPT 哪一版更强，不把 DeepSeek Harness、Hermes 并进本文。

## 它由什么构成

**harness（执行环）**：会话状态、流式执行、工具调用、沙盒与审批策略、跨轮接续。OpenAI 的定义比「带工具的 chatbot」硬：还要暴露进度、处理失败、必要时停下来等人。官方给过一个可核对的数字：在 ARC-AGI-3 上，保留推理轨迹并做 context compaction 之后，GPT-5.6 Sol 从 13.3% 升到 38.3%，输出 token 降到约六分之一。同一套权重，换环，分数会变。

**三层接入**，对应三种活法：

| 层 | 适合 | 它管什么 |
|---|---|---|
| `codex exec` | 脚本、CI、一次性后台任务 | 有界地跑完一轮，吐结构化结果 |
| Codex SDK | 应用代码里启动 / 续跑 / 订阅流 | 程序化控制线程；Python / TypeScript |
| Codex app-server | Agent 就是产品的一部分 | 本地长进程 + JSON-RPC：建线程、开一轮、收事件、打断、回审批 |

**App Server 进程内部**（官方架构文）：stdio 读入、消息处理器、线程管理器、若干 core thread。一个 App Server 可以挂多条会话；客户端要自己实现 JSON-RPC 绑定，换来的是生命周期和 UI 不被 CLI 外观锁死。

**沙盒与审批**：SDK 里能看到 `Sandbox.workspace_write` 这类预设，以及按 turn 覆盖审批模式。写操作默认不是「模型说写就写」。开源清单包括 CLI、`codex-rs` 核心、SDK、app-server、安全 CLI、Skills/Plugins 仓库；IDE 插件、Codex Cloud、模型权重不在开源包里。

**应用侧该留下的**：队列、记录、权限矩阵、业务 MCP、人已经在看的界面。官方用 Relay：选中一票货运 → 点「Compare recovery」→ 应用塞上下文 → Codex 调应用自己的 MCP 拉样例数据 → 解释选项 → 改预定必须批准 → 记录变更后界面刷新。人不是从空白 prompt 开始。

## 理念怎么落进机制

主线：**产品拥有上下文和闸门，harness 拥有循环。**

如果把业务规则写成超长 system prompt，换一次接入层等于重做项目。正确切法是：应用决定「此刻屏幕上是哪张单、哪些工具能见、哪类写要人批」；harness 决定「工具怎么串、失败怎么重试、沙盒怎么执行、事件怎么流回来」。

选哪一层可以按「要不要自己画 UI」判断。只要结果、不要会话：`exec`。要在自己的服务里起任务：SDK。要把调查台、审批按钮、中断做成产品：app-server。官方举过 Cisco Cloud Control 的 App Builder 用 SDK、税务工作流试点处理约 7000 份申报、准备时间降约三分之一——这些是嵌入叙事，不是你必须复用的行业方案。

和「再做一个 Codex 皮肤」的差别：皮肤复制的是聊天窗；平台复制的是线程、事件、审批这组状态机。

一个容易漏的细节：沙盒参数挂在 **turn** 上，一次线程里后面几轮会继承，除非再覆盖。这意味着「先只读调查、后写入修复」可以做成两次 turn，而不是两个 agent。审批同理。若应用把只读和写入揉在同一轮，harness 的闸门就只剩下「整轮批或不批」，细粒度白做了。

`codex mcp-server` 在现行 SDK 文档里标成 deprecated。工具暴露的正道是应用自己的 MCP，加上 harness 去调，而不是再起一个「Codex 变身 MCP 服务器」的兼容层。这和 Relay 的切法一致：业务工具属于应用。
