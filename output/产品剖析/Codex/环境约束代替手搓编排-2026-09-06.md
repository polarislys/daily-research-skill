# OpenAI Harness Engineering：人设计环境，Codex 写代码

**一句话**：工程师主要写任务说明；代码由 Codex Agent 产出；精力花在 **harness**——仓库规则、CI、worktree 隔离、可查询的 observability，让 Agent 能自己验 PR。

日期：2026-09-06

---

## 这是个啥

[Harness engineering](https://openai.com/index/harness-engineering/) 是 OpenAI 团队的做法：几个月做出很大的内部产品，**业务代码几乎全是 Codex 写的**。人很少直接改源码，而是设计 harness、下 prompt、审 PR。

## 三个机制（白话）

**① git worktree 隔离**  
每个任务单独 worktree + 临时 observability（log / metric / trace）。Agent 能用 LogQL、PromQL 查「改完有没有炸」。

**② 规矩进 repo，不靠嘴**  
`docs/` 放架构与规格；`AGENTS.md` 只做目录。CI、linter、结构测试 **机械拦** 坏合并。

**③ PR 自审 + agent review 环**  
Codex 本地自审 diff，再拉 cloud agent review，评论改到过关再请人。人不再是唯一 QA。

## harness 是什么

**harness** = 模型外的 loop、tool、权限、文档结构、反馈环。OpenAI 的观点：Agent 上下文里没有的东西，对它就等于不存在——所以要把 **验收方式** 也做成它能读的环境。

和 Anthropic 多 Agent 互盯不同，这篇更强调 **repo + CI 当约束**；共同点：模型变强后旧 harness 假设会过时，接口要能换。
