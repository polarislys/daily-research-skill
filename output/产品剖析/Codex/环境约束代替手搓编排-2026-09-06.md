# OpenAI 的 Harness 工程：少手写代码，多设计「Agent 跑不坏的环境」

**一句话**：人主要写任务说明；代码让 Codex 写；真正花精力的是——仓库规则、自动测试、隔离环境，让 Agent 自己验自己的 PR。

日期：2026-09-06

---

## 这是个啥

OpenAI 团队写了一篇 [Harness engineering](https://openai.com/index/harness-engineering/)：他们用 Codex Agent 几个月做出一个很大的内部产品，**业务代码基本全是 Agent 写的**。人几乎不直接改源码，而是：

1. 用自然语言描述任务  
2. Agent 开 PR  
3. 环境里的测试、规范、日志帮 Agent（和人）判断能不能合

## 三个做法，白话版

**① 每个任务单独开一间屋（git worktree）**  
并行改代码不打架；旁边还挂着日志、指标，Agent 能自己查「改完有没有炸」。

**② 规矩写在仓库里，不靠嘴说**  
架构说明、检查清单放在 `docs/`；`AGENTS.md` 只做目录，指向详细文档。CI、linter、结构测试 **机械拦** 不合规范的合并。

**③ PR 上自审 + 互审**  
Agent 改完先自己看 diff，再拉别的 Agent review，评论改到过关再请人。人不再是唯一 QA。

## 为啥叫 harness（夹具）

模型像马力很大的马，harness 是缰绳、马鞍——**不让它乱跑，而是往你要的方向拉**。OpenAI 的观点：Agent 看不到上下文中没有的东西，所以要把「验货方式」也做成它能读的环境（包括日志查询）。

## 和 Anthropic 路线比一眼

Anthropic 长任务常拆多个 Agent 角色互相盯；OpenAI 这篇更强调 **代码库 + CI 当约束**。两边都说：模型变强后，旧假设会过时，夹具要能动、能换。
