# iStar 用轨迹 DPO 训出隐式 PRM，把 agent RL 的步级 credit 从标注里解耦

这篇读 Tongyi Lab 等团队的 **iStar**（implicit step rewards for agentic RL，arXiv:2509.19199）：在 **不增 rollout、不要 step 标注** 的前提下，用 **轨迹级 DPO** 交替优化隐式 process reward model（PRM），产出 **步级 advantage**，再与 episode-level advantage 合成，挂到 GRPO 等标准 RL 上。它与 TIGPO/PGPO 同答 credit assignment，但路线是 **从 preference 学 reward**，不是改 graph 或势函数。

## 旧路为什么不够

Agentic RL 的三难：**reward 稀疏**、**轨迹长且 token 级非 Markov**（一步 = CoT + executable action，方差在 token 上爆炸）、**环境开放且 reward 有时不可验证**（社交对话只有 judge 分）。纯 episode return 的 GRPO/RLOO 把整局成败压到每个 action，**探索脆、样本效率低**。

Process supervision 能密化信号，但 **人工 step label 贵、偏、易被 reward hacking**；LLM-as-judge 的 GRM **跨域噪声大**；单轮 alignment 里的 **token-level implicit reward** \(r_\phi(y_t) \propto \log\frac{\pi_\phi(y_t|y_{<t})}{\pi_{\mathrm{ref}}(y_t|y_{<t})}\) 迁到 agent 时 **粒度过细**，长轨迹上方差反而放大、训练不稳。GiGPO 靠 **相同 state 分组** 算 step advantage——在开放语言环境里 observation 几乎不重复，假设常失效。

论文的核心问法：**有没有 label-efficient、稳、能统一可验证与不可验证 reward 的 credit 策略？** iStar 的回答是把 DPO 从「偏好两条单轮回复」改成「verifier 偏好两条完整轨迹」，再把 induced reward **投影到 step**，而不是另训逐步 GRM 或手工 process label。

## 机制：iStar 的交替优化环

iStar 维护 **policy \(\pi_\theta\)**（LLM agent）与 **implicit PRM \(\pi_\phi\)**，每 training step 走一条闭环：采样 → 排序 → 更新 PRM → 算 step reward → 更新 policy。下面分三步说清 **输入、中间态、梯度落在哪**。整条链路 **不额外采样 rollout**——相对显式 PRM，算力主要多一个 \(\pi_\phi\) 训练步，这是 iStar 相对 graph/TIGPO 系的工程卖点；tradeoff 是 verifier 排序质量决定天花板，judge 升级等价于换 reward 函数。

**Rollout 与偏好对**：\(\pi_\theta\) 与环境交互得多步轨迹 \(\tau\)；**outcome verifier**（规则、环境反馈或 reward model）给轨迹排序，构 \((\tau^+, \tau^-)\)。WebShop / VisualSokoban 以任务成功为准；SOTOPIA 社交模拟用 goal completion 阈值——刻意覆盖 **unverifiable** 场景，偏好来自 outcome 而非逐步标签。

**训 implicit PRM**：轨迹级 DPO，参考模型是 **上一轮 policy snapshot \(\pi_{\theta_{\text{old}}}\)**（非常规 DPO 的 frozen initial SFT），偏好学 **整轨迹** 而非单回复。优化后 PRM 对每步 action 给出 **implicit step reward**：
\[
r_\phi(o_{1:t}, a_t) = \beta \log \frac{\pi_\phi(a_t|o_{1:t}, x)}{\pi_{\theta_{\text{old}}}(a_t|o_{1:t}, x)}
\]
正号表示 PRM 认为该步相对旧 policy **更 responsible for improvement**。理论（§3.2）证：该目标等价 Bradley-Terry + **step-wise reward 分解**——轨迹偏好求和变成逐步 reward 之差，粒度是 **action 级**（整段 CoT+tool call），不是 token 级，控方差。

**Policy 更新**：对同一 prompt \(x\) 采样 N 条轨迹，outcome 组内标准化得 **episode advantage** \(A^E(\tau_i)\)（GRPO 式）；用最新 \(\pi_\phi\) 算每步 \(r_\phi\)，在 **同组所有步** 上标准化得 **step advantage** \(A^S(a_t^i)\)；合成 \(A = A^E + \alpha A^S\)。Surrogate 用 **step-level importance ratio** \(\rho_\theta(a_t)\) 与 clip——与长轨迹低方差设定一致（论文对照 Zheng 等 step-level PPO 变体）。式 (7)(8) 说明 trajectory DPO 最优解诱导的 \(r_\phi^*\) 是 **逐步可加** 的——这是 iStar 敢把 PRM 当 process reward 的理论底气，而不是 heuristic 加权。

交替优化节奏上，典型一步是：先 rollout → 排序 → 更新 \(\pi_\phi\) → 用新 \(\pi_\phi\) 算 \(r_\phi\) → 更新 \(\pi_\theta\)。论文 Remarks 强调 **同分布 rollout** 减轻 covariate shift：若 PRM 落后 policy 太多，implicit reward 会 ** miscalibrated**；若 PRM 过快过拟合少量偏好对，step signal 会 **带偏探索**。这是所有 online RM 的共同张力，iStar 用 moving reference 缓解，但不消除。

环是 **self-reinforcing**：policy 变好 → 偏好对更有信息 → PRM 更准 → 步奖励更密 → policy 再更新；**同一批 online rollout** 训两边，减轻 off-policy drift。论文强调：从 **同初始 state 的多条轨迹** 可构造 counterfactual，步级 baseline 更稳；单轨迹内不同 state 混比，方差高——这与 GRPO 组内相对比较哲学一致。VisualSokoban 说明 iStar 不限于文本 web：**只要 outcome 可排序、action 可逐步生成**，implicit PRM 就 work；终局 verifier 接口在购物与推箱环境可统一。

**Rollout 与偏好对**再深入半步：positive/negative 轨迹来自 **同一 \(\pi_\theta\) 的组内采样**，不是 offline 人类偏好——因此 iStar 是 **online RL + online RM**，数据分布随 policy 动。Trajectory DPO 里用 \(\pi_{\theta_{\text{old}}}\) 当 reference，等价问「相对上一版 policy，PRM 更偏好哪条完整路径」；逐步 reward 则是把路径偏好 **局部化到 action**，使 GRPO 不必整轨迹共用一个标量。Reference 随 policy 更新，适合 non-stationary agent，但要监控 PRM 是否 lag。

## 对照 GRPO、显式 PRM、TIGPO/PGPO

相对 **vanilla GRPO**：iStar 能区分「整局失败但前几步优于组内其他失败」的步——与 PGPO 的 failure-side 目标相近，但信号来自 **learned preference**，不需 anchor-state 重叠。

相对 **显式 PRM / step 标注**：不依赖 costly process label，也不依赖 token-level implicit PRM 的细粒度噪声。

相对 **TIGPO**：iStar 不维护 cross-update graph；**正交**，能否组合未测。iStar 更偏 **reward model 学习**；TIGPO 偏 **结构记忆 + Revisit 采样**。

实验：WebShop、VisualSokoban 报 SOTA 级；SOTOPIA 对 GPT-4o 对聊 goal completion **+48%**，self-chat **+14%**；可 plug RLOO、DAPO。分析称 **步级与 episode 级 reward 同步上升** 且 **成功所需步数减少**——探索效率叙事。代码 **will be available soon**。

读 iStar 时要分清 **两层 verifier**：环境给的 0/1（WebShop）与 **模型 judge**（SOTOPIA）。后者让 iStar 看起来能训「无 ground truth」对话 agent，但其实是 **把 ground truth 外包给 judge**——和 RLHF 一样，judge 升级等于 reward 函数升级。iStar 的贡献是 **在 judge 之后仍拆 step credit**，而不是 Eliminate judge。对 coding agent，若你以 **CI 通过 + PR review** 为 outcome，轨迹偏好对天然存在（green vs red pipeline），iStar 叙事与 **用 merge 结果训 policy** 的想象相近，但论文尚未在 SWE-bench 类环境验证。

与 **显式 PRM**（逐步 Bradley-Terry 标注）比，iStar 少 **标注成本**，多 **一轮 \(\pi_\phi\) 训练计算**；与 **GRM 逐步打分** 比，iStar 的 step reward 来自 **同一 PRM 的自洽分解**，不是每步单独 call judge——latency 与一致性可能更好，需等代码。Token-level DPO reward 在单轮已证可行；iStar  essentially 把 **step 当 macro-token**，这是 agent 场景里合理的 bias-variance tradeoff。

## 还不能信什么

**单篇预印本**；outcome verifier 质量天花板即 PRM 天花板——SOTOPIA 的 judge 一致性未独立审计。Moving reference \(\pi_{\theta_{\text{old}}}\) 与 DPO 经典设定不同，外推需谨慎。与 hand-engineered verifier 强的环境（SWE-bench 类）是否增益相当，论文未覆盖。Alternating \(\pi_\phi\) 与 \(\pi_\theta\) 是否比 joint batch 更稳，ablation 有限；小 batch 时 trajectory pair 可能不够 diverse，PRM 过拟合单类失败模式。step + episode 双 advantage 可能 **双重计数** 同一成功，\(\alpha\) schedule 未充分公开；训练需额外 **PRM 参数量**，部署时要算双模型成本——推理若只用 \(\pi_\theta\)，则 iStar 是纯训练算法，这点与线上 rerank 场景要分开想。

Implementation 细节上，iStar 与 **Cui 等 token-level implicit PRM** 的分野值得写进你的 mental model：后者每个 token 一个 reward，适合单轮回复；iStar 把 **一步定义为完整 action 序列**（含 CoT），advantage 也在 step 上聚合，避免 multi-turn 里 token 噪声累积。与 **DPO 原版** 的分野：参考模型是 **moving \(\pi_{\theta_{\text{old}}}\)** 而非 frozen SFT，偏好是 **轨迹对** 而非单回复对——这让 PRM 跟踪 policy 漂移，但也意味着理论 guarantees 成立域更窄，训练需盯 **PRM 与 policy 是否同步过快** 导致 collapse。

与 **GRPO 拼接** 时，\(\alpha\) 平衡 episode vs step advantage：\(\alpha\) 过大可能 **过拟合 PRM 短期偏好** 而忽视终局成功；过小则退回 sparse。论文在 WebShop 报 **更少步数达成成功**，说明 step signal 在引导探索长度上有效——这与 process reward 的经典动机一致，但无需人标每一步。Plug 进 RLOO/DAPO 的结果表明 iStar 是 **advantage 模块** 而非全新 RL 栈——对你意味着 trial cost 主要在 **多训一个 \(\pi_\phi\)** 和调 \(\alpha\)，而非重写 rollout worker。

Social benchmark SOTOPIA 结果说明 iStar 不绑 **可验证终局**——只要 outcome model 能排序轨迹，implicit step reward 仍可生成。这打开 **对话策略、negotiation agent** 的训练想象空间，但也把风险推给 judge：**judge 偏了，PRM 学偏，policy 放大偏**。与 RLHF 相同的老问题，只是 credit 更细了。论文 claim 的 sample efficiency 需等开源复现 **同等 verifier 成本** 下对比 GRPO steps-to-success，不宜只看最终 score。

和 **TIGPO/PGPO** 正交：iStar 不学 graph、不算势函数；若环境有清晰状态图（游戏、购物），TIGPO 可能更 sample-efficient；若失败轨迹多、状态难对齐，iStar 的 preference 路径可能更稳。是否 **iStar step reward + TIGPO graph advantage** 可加性合并，论文未测，是合理的 open experiment。对实践者，一条决策树是：**有 repeatable state 且同一 task 会反复试 → 看 TIGPO；只有终局 reward 但组内多条轨迹 → 看 PGPO 或 iStar；有 cheap outcome 排序无 step 标 → 优先 iStar**。三者都不是 inference-time trick，训练栈改动成本相当。等代码公开后，第一件事应是对 **同一 verifier** 做 GRPO vs iStar 的 steps-to-success 曲线，而不是只比 final score。Bradley-Terry 逐步分解（式 7–8）说明 implicit step reward 不是 heuristic，而是 trajectory DPO 最优解的 **可加结构**——复现时跳过 PRM、手工加权 step，通常会失去 self-reinforcing loop。

我的判断：**iStar 把 alignment 里成熟的 trajectory preference 搬进 agent RL，用一步公式把「要不要 step 标注」换成「要不要可靠的 outcome 排序」**——若你已有测试/规则/judge，它是比 GraphGPO 更轻的 densify 路径；若没有 verifier，环仍回到 sparse reward 原罪，implicit PRM 无 preference 可学。

WebShop 微观例子：同一 prompt 采样 N 条轨迹，一条买到目标商品、一条购物车空——outcome verifier 排序得 \((\tau^+, \tau^-)\)；trajectory DPO 训 \(\pi_\phi\)，对「加购第 3 步」给出正 implicit step reward，对失败轨迹里 **同样加购但后续选错 SKU** 的步给负 signal——GRPO alone 会把整局失败压到每步。式 (7)(8) 的逐步可加分解是理论底气：不是 heuristic 混权 \(\alpha\)，而是 DPO 最优解诱导的 \(r_\phi^*\) 结构。与 Warp DPO 对照：Warp 在 **组织偏好** 上训 model 权重；iStar 在 **环境 outcome** 上训 PRM 再喂 policy——前者要 data pipeline，后者要 verifier，都不免 preference 质量天花板。Coding agent 若用 CI green vs red 构轨迹对，iStar 叙事贴近 **merge 结果训 policy**，但 SWE-bench 尚未验证；trial 时先盯 PRM 与 \(\pi_\theta\) 是否 sync，lag 会导致 step reward miscalibrated。

SOTOPIA +48% goal completion 说明 iStar 不绑可验证终局——但 judge 偏了 PRM 学偏、policy 放大偏，与 RLHF 同老问题。推理部署若只用 \(\pi_\theta\)，iStar 是纯训练算法；双模型成本要在 trial 预算里单独列。alternating 优化里 reference 用 moving \(\pi_{\theta_{\text{old}}}\) 而非 frozen SFT——跟踪 policy 漂移，但理论保证域更窄。
